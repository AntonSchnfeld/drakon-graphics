## Release target

A small but real, usable 3D graphics library that can drive the same basic renderer on OpenGL and Vulkan without application rendering code touching either native API.

### Status

- ✅ Already present in the current codebase. `present; release validation still required` means the implementation/API exists but still needs a specific 0.1.0 acceptance workload.
- ☐ Required for 0.1.0 but not yet implemented or complete enough to count as supported.
- — Explicitly deferred beyond 0.1.0; not a release blocker.

Current locked-scope checklist totals (excluding the three status-key examples above): **250 present**, **28 present but still needing release proof**, **130 open required items**, **101 deferred items** (**509 total**).

## Definition of done

The release is ready when a small reference application can render a perspective, depth-tested, textured 3D scene with changing per-frame data, multiple objects, alpha blending and an offscreen pass; can resize and run for several minutes; and can switch between OpenGL and Vulkan without changing the portable rendering code. The detailed validation, documentation, packaging, platform and release-process requirements below must also be complete.

## 1. Release definition

- ✅ Java 21 low-level graphics library with a backend-neutral public core.
- ✅ OpenGL and Vulkan are implemented as separate backend modules.
- ✅ Application rendering code can use portable Drakon resources, commands, state, bindings and render targets instead of native OpenGL/Vulkan calls.
- ☐ 0.1.0 must be usable as a simple real-time 3D graphics library rather than merely as a backend spike.
- ☐ The final 0.1.0 acceptance application must run the same renderer on OpenGL and Vulkan, with backend/bootstrap and shader representation as the only intentional differences.
